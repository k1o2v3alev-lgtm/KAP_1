# Ядро ЦОМ (engine)

Универсальное ядро цифрового образовательного материала по КСП: **ученический файл**, **кабинет учителя** (анализ результатов и бумажные комплекты), единая схема отчёта и общие правила оценивания. Реализует требования из `MASTER_PROMPT_COM_KSP_1-11_UNIFIED.md` (разделы 7–14, 17–18, 23–26, приложения A–C).

Результат сборки — два автономных HTML-файла без сервера, интернета и внешних библиотек:

| Файл | Назначение |
|---|---|
| `dist/<набор>/student_material.html` | Ученику: «Мои уроки», этапы урока, подсказки, коррекционный цикл, отчёт, сохранение результата в файл |
| `dist/<набор>/teacher_console.html` | Учителю: импорт результатов, анализ, проверка открытых ответов, бумажный комплект (варианты, бланки OMR, ключи), ручной ввод результатов бумаги |

Содержание урока (`content/<набор>/pack.js`) встраивается в оба файла из одного источника, `contentHash` у них одинаков.

> **Содержание в `content/demo/` — демонстрационное.** Оно нужно для проверки ядра на двух предметах (математика 6, информатика 8) и **не является КСП** и не привязано к программе РК.

## Быстрый старт

Нужен Node.js 18+ (для сборки и тестов). Пакетов устанавливать не нужно; для браузерных испытаний используется Playwright с Chromium.

```bash
cd engine
node build/build.js demo      # собрать dist/demo/student_material.html и teacher_console.html
node tests/run-node.js        # тесты ядра, генераторов, бумажного комплекта, адаптеров (без браузера)
node tests/browser/student.test.js   # испытания ученического файла в Chromium
node tests/browser/teacher.test.js   # испытания кабинета учителя в Chromium
```

Готовые файлы можно просто открыть в браузере. Служебная самопроверка ученического файла: добавить `#selftest` к адресу.

## Устройство

| Слой | Каталог | Что делает |
|---|---|---|
| Ядро | `src/core/` | ГСЧ с seed, нормализация и проверка ответов, разбор выражений без `eval`, оценивание, генераторы и валидатор, схема отчёта, адаптеры прежних схем |
| Ученик | `src/student/`, `src/styles/` | Интерфейс и словарь строк (ru, kk) |
| Учитель | `src/teacher/` | Кабинет, бумажный комплект (`paper.js`) |
| Содержание | `content/<набор>/pack.js` | Уроки из КСП, генераторы, критерии, дескрипторы, подсказки об ошибках |
| Сборка | `build/` | Склейка в два HTML, вычисление `contentHash` |

Принцип: **ядро не переписывается под урок**. Новый продукт — это новый `pack.js` на том же ядре (раздел 23.2 промта).

## Как создать продукт

1. Создай `content/<имя>/pack.js` по образцу `content/demo/pack.js`: задай `K.PACK` (уроки) и зарегистрируй генераторы через `KAP.gen.register`.
2. Урок (`lesson`): цели, критерии и дескрипторы из КСП, поднавыки (с карточками правил и рекомендациями), этапы по единому каркасу: `entry` → `diagnostic` → `open` (карточки) → `train` → `practice` → `final` → `club` → `reflect`. Веса КСП задаются в `weights`, лимит времени проверки в `timeLimitSec.final`.
3. Генератор: `generate(rng, профиль)` возвращает условие, ключ и дистракторы, **вычисляя ответ из параметров**. Нужные поля: `id`, `version`, `taskType`, `subskill`, `cognitiveLevel`, `profiles`, `generate`. Типы заданий: `single_choice`, `multi_choice`, `number`, `text`, `expression`, `base`, `ordering`, `matching`, `open`.
4. Собери: `node build/build.js <имя>`.
5. Прогони `node tests/run-node.js` (в том числе массовые тесты каждого генератора) и браузерные испытания.

## Что реализовано и проверено

Проверено запуском (на момент сдачи):

- **Тесты без браузера (71):** ГСЧ и воспроизводимость; нормализация (латинские двойники, `ә ≠ а`); эквивалентные записи чисел и выражений (B1, B2, B14); частичное оценивание; коэффициенты подсказок и попыток (B22); профили весов и приоритет источников (B21); формативная отметка без проверки; потолок 84% только для контрольных работ и итогового профиля; освоение поднавыка и статусы дескрипторов (B24); итог по уроку «среднее лучшей и последней» (B25); **массовое тестирование каждого генератора и профиля по 600 генераций** с проверкой уникальности, позиции правильного ответа, перекоса «самый длинный», воспроизведения по seed; **100 построений бумажных комплектов** с проверкой равноценности вариантов; кодирование и контроль кода бланка; адаптеры прежних схем на обезличенных образцах; статическая проверка собранных файлов (нет `eval`, нет внешних адресов, одинаковое содержание).
- **Браузер, ученик (14 сценариев, Chromium):** полный проход урока через интерфейс; сохранение файла результата; восстановление после перезагрузки; новая попытка с новыми вариантами; коррекционная серия; «Закончить на сегодня» и продолжение; контрольная работа с превышением времени; отсутствие служебных слов на экранах (B15); самопроверка; ширины 360 и 430 px.
- **Браузер, учитель (14 сценариев, Chromium):** импорт одного/нескольких файлов и пакета; дубликаты; прежний формат; повреждённый файл; предупреждения о версиях; итог по уроку; проверка открытых ответов с пересчётом; защита от вредного HTML; воспроизведение по seed; составление комплекта, печать (PDF), сохранение комплекта, ручной ввод результатов; CSV; ширины 360 и 430 px.
- **Реальный корпус (78 файлов прежних разработок, не входит в репозиторий):** все распознаны, получено 88 отчётов, замечаний нет. Запуск: `node tests/corpus.js <папка>`. Корпус содержит персональные данные; скрипт печатает только счётчики.

## Известные ограничения и допущения

- **Распознавание OMR-бланков по фото не реализовано** (в кабинете оно помечено «не проверено, отключено»). Реализованы и проверены: самоидентифицирующийся код бланка с контролем чётности и суммы, печать бланка, ключи, ручной ввод. Печать на бумаге и сканирование реальных бланков не проверялись.
- Браузерные испытания выполнены только в headless Chromium. Firefox, Safari, реальные смартфоны и проекторы не проверялись. Доступность проверена на уровне разметки и клавиатуры, не с экранным диктором.
- Казахские строки интерфейса (`src/student/i18n.js`) — рабочий вариант, требуют проверки носителем языка; недостающие берутся из русского словаря.
- Перетаскивание (drag-and-drop) в заданиях не реализовано: порядок и соответствия задаются кнопками и списками (это и есть мобильная альтернатива).
- Активное время считается по событиям взаимодействия (интервал до 120 с); чтение без касаний дольше 2 минут в рабочее время не входит. Календарное время и сессии записываются отдельно.
- Потолок 84% при превышении времени применяется ко всей отметке попытки, если это контрольная работа (ПО, СОР, СОЧ) или итоговый профиль. Это допущение из раздела 14.4 промта.
- Возвратные (коррекционные) задания учитываются в освоении поднавыков, но не входят в отметку и в долю выполнения.
- Данные кабинета учителя хранятся в памяти страницы; после перезагрузки их нужно загрузить заново.
- Состояние ученика хранится в `localStorage` конкретного браузера; синхронизации между устройствами нет. Экспорт и импорт незавершённой сессии (`session_snapshot`) схемой предусмотрен, в интерфейсе пока не реализован.
- Ключи ответов в ученическом файле технически доступны через код страницы: для контроля с высокими последствиями используй бумажный или очный формат.
